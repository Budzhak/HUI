# Количество

![Количество](../img/icons_bg/Количество.png)

↩ [XYZ](../../README.md)

> [!NOTE]
> **Что делает**
> Считает количество для спецификации с запасом — длину, площадь или штуки — и пишет его в ADSK_Количество или ADSK_Размер_Площадь. Считает по правилам, которые видны в окне и правятся там же. Сначала показывает пробу «было → станет», в модель пишет только по кнопке «Применить».

## Демонстрация
> [!TIP]
> GIF с работой кнопки появится здесь: `img/gif/Количество.gif` (запишем позже).

## Когда применять
- Перед выдачей спецификации: после моделирования, после чужих надстроек, которые пересчитывают количество.
- Когда поменялись запасы (например, «на гибкие — 10 %»).
- Чтобы проверить, что всё попало в своё здание (режим «Только проверить»).

## Как пользоваться
1. Нажмите «Количество». Откроется окно из трёх шагов.
2. **Шаг 1 «Где»:**
   - область: выделенные элементы, активный вид или вся модель;
   - рабочие наборы: снимите лишние, например теплоснабжение или отверстия;
   - здание по областям видимости: отметьте рамки здания (см. ниже);
   - «Записать ADSK_Номер здания по рамкам»;
   - «Пропускать позиции «!Не учитывать…»»;
   - режим: «Посчитать и показать пробу» или «Только проверить».
3. **Шаг 2 «Правила»** — таблица: категория + условие → как считать → куда писать → запас, %. Колонка «Поймано» показывает, сколько элементов попало под строку.
4. **Шаг 3 «Проба»** — вкладки «Итог по позициям», «Элементы», «Здание ≠ рамка», «Вне рамок», «Без данных», «Без правила».
   - Двойной щелчок по строке выделяет и показывает элемент в модели.
   - «В Excel» выгружает текущую вкладку.
5. Отметьте, что записывать: «Записать количество», «Записать ADSK_Номер здания», и нажмите **«Применить»**.

## Режимы и настройки
- **Правила проверяются сверху вниз.** Для каждого параметра («Куда писать») элемент берёт первое подошедшее правило, поэтому частное правило (например, «db_Категория = 23» — дренаж ППР) ставится выше общего.
- **Условие**: элемент или его **основа** (для изоляции), параметр из тех, что есть у элементов, знак (=, ≠, содержит, не содержит, начинается с), значение из тех, что есть в модели. В скобках у значения — сколько элементов.
- **Как считать:**

| Способ | Что берётся |
|---|---|
| длина, м | длина элемента; у изоляции на фасонке — длина фасонки по соединителям |
| площадь поверхности, м² | поверхность элемента (воздуховод) |
| ADSK_Размер_Площадь, м² | значение параметра |
| поверхность основы, м² | поверхность воздуховода или ADSK_Размер_Площадь фасонки, без её запаса |
| поверхность основы + её запас, м² | то же × запас основы по её правилу |
| длина основы + её запас, м | длина трубы × запас трубы по её правилу |
| штуки | 1 |

- **Запас изоляции от основы с запасом.** Медь +10 % и изоляция +20 % дают 1,10 × 1,20 = 1,32 длины трубы; ППР +20 % и изоляция +20 % — 1,44. У изоляции на отводах и тройниках берётся запас присоединённой трубы или воздуховода. Как получилась каждая цифра — колонка «Как посчитано» на вкладке «Элементы».
- **Округление** — до 0,01. Значение, которое уже совпадает с расчётом (±0,005), не переписывается.
- **Файл правил.** «Открыть…», «Сохранить», «Сохранить как…», «Вернуть из файла», «Стандартные». Кнопка запоминает выбранный файл для модели (по пути хранилища). По умолчанию файл лежит рядом с моделью: `<имя файла модели>_XYZ_Количество.json`. Строка под таблицей показывает, совпадают ли правила в окне с файлом. Правила — это файл, а не модель, поэтому сохранять их можно и в режиме «Только проверить».
- **Здание по рамкам.** Область видимости («Вид → Создание → Область видимости»), имя — значение ADSK_Номер здания. Хвост « (1)», « (2)» отбрасывается, так что Г-образное здание обводится двумя рамками. Элемент в рамке, если центр его габарита внутри рамки и в плане, и по высоте. Низ рамки ставится на уровень плана, на котором её рисовали, — проверьте высоту в разрезе.

## Что меняется в модели
- ADSK_Количество и/или ADSK_Размер_Площадь (площадь Revit хранит в футах², кнопка пересчитывает сама).
- ADSK_Номер здания — если отмечено «Записать ADSK_Номер здания».

## Изменения 21.10.2026 (вечер)
- **Медь: факт и смета раздельно.** Новый параметр db_Количество_факт (трубы и соединительные детали трубопроводов): длина по оси (у отводов — по дуге), округление до 0,001. Таблицы фреонопроводов на схемах показывают факт; ADSK_Количество = факт × 1,05 — в итоговую спецификацию. Правила в файле db: 4 правила меди.
- **Здание вне рамок.** Вкладка «Вне рамок» — столбец «Станет» и галочка «Убрать ADSK_Номер здания у элементов вне рамок»: элемент вне рамки получает здание другой рамки или пусто (db: коммуникации копируют в другие строения, а параметр остаётся «Основной дом»).
- Элементы без габарита (гибкие воздуховоды) теперь попадают в рамку по середине оси / точке / основе (`_center`).

## Ограничения и подводные камни
- Если после кнопки запустить другую надстройку, пересчитывающую количества, она перепишет их по своим формулам.
- Параметр «только для чтения» (формула в семействе) не пишется — он попадёт на вкладку «Без данных».
- Элементы без габарита не попадают ни в одну рамку.
- Здание в параметре — это снимок на момент запуска. Нарисовали новое или передвинули рамку — запустите кнопку ещё раз или проверьте режимом «Только проверить».
