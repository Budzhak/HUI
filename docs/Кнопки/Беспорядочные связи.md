# Беспорядочные связи

> [!NOTE]
> **Прежнее название:** «Параметры связи» (переименовано 17.10.2026 по решению db).

![Беспорядочные связи](../img/icons_bg/Беспорядочные%20связи.png)

↩ [ХУЙ](../../README.md)

> [!NOTE]
> **Что делает**
> Переносит общие параметры из связи (IFC или RVT) в ваш проект с тем же GUID и категориями. После этого по ним можно строить фильтры видимости для элементов связи (например, IfcPresentationLayer, ArchiCADProperties.*). Значения в проект не копируются, они остаются в связи.

## Демонстрация
> [!TIP]
> GIF с работой кнопки появится здесь: `img/gif/Параметры связи.gif` (запишем позже).

## Когда применять
Нужно раскрасить или скрыть элементы связи по их параметру, а в «Фильтры → Критерии фильтрации» этого параметра нет.

## Как пользоваться
1. Нажмите «Параметры связи». Окно «Параметры связи»: «Добавить параметры из связи» или «Убрать параметры, добавленные этой кнопкой».
2. **Добавить:**
   1. Окно «Из какой связи взять параметры» (если загруженных связей больше одной). У каждой подписан тип: IFC или RVT.
   2. «Часть имени параметра»: по умолчанию `Ifc`. Несколько слов через пробел — все должны входить в имя. Пустое поле — все параметры (в IFC их десятки тысяч).
   3. Список параметров, которых нет в проекте. Заранее ничего не отмечено, работает поиск. У каждого параметра видно: тип или экземпляр, «новый» или «дополнить категории (+N)», число категорий. Отметьте нужные → «Дальше».
   4. «К каким категориям привязать». Отметьте только нужные, например «Перекрытия» → «Дальше».
   5. Подтверждение со списком параметров и категорий → «Да».
   6. Отчёт в окне вывода: «Создано», «Дополнены категории», «Ошибки», «Не переносятся» (с причиной).
   7. Вопрос «Показать значения этих параметров в связи?». При «Да» выводится таблица значений с числом элементов — по ней удобно составлять правило фильтра.
3. **Убрать:** список параметров, добавленных кнопкой → отметить → «Убрать из проекта» → подтвердить.

## Режимы и настройки
- **Shift+клик** — диагностика без изменений: выбор связи, фильтр по имени, таблица «Параметр / GUID / Привязка» и сводка по числу общих параметров.
- Показывается не больше 1500 параметров-кандидатов. В таблицах окна вывода — до 300 строк, полный список сохраняется в `%TEMP%\hui_link_params_report.txt`.

## Что меняется в модели
- В проект добавляются общие параметры (тот же GUID, имя и тип данных; экземпляр или тип — как в связи), привязанные к выбранным категориям. Группа в ФОП — `HUI_Параметры_связи`. В описании стоит пометка `HUI-link · из связи «…»`.
- У параметров, которые уже есть в проекте, расширяется список категорий.
- Режим «Убрать» удаляет привязку и SharedParameterElement.

## Ограничения и подводные камни
- Переносятся только **общие** параметры (с GUID). Обычные параметры проекта связи сопоставить не с чем.
- Если в проекте уже есть параметр с тем же именем, но другим GUID, он пропускается.
- Фильтр действует на связь, только если у неё стоит «По основному виду» («Видимость/Графика → Revit-связи»).
- «Убрать» удаляет только то, что помечено `HUI-link`. Фильтры и спецификации, в которых эти параметры используются, перестанут работать.
- Пока идёт добавление, кнопка временно подменяет файл общих параметров Revit, а потом возвращает прежний.

## Отмена
Добавление и удаление выполняются одной транзакцией, отмена — Ctrl+Z. Позже добавленное можно убрать этой же кнопкой (режим «Убрать»).

## Техническое (для Claude)
- `script.py`: `analyse` → кандидаты по `read_bindings(ldoc, tokens)`; GUID берётся из `key.GUID` или из `SharedParameterElement` с тем же Id.
- `import_params`: временный ФОП `%TEMP%\hui_link_params_<pid>.txt`, записывается байтами в UTF-16 (с заголовком или пустой), `ExternalDefinitionCreationOptions` с GUID, `ParameterBindings.Insert/ReInsert`, группа по умолчанию — `GroupTypeId.Ifc`.
- `remove_added`: ищет по `Description.startswith('HUI-link')`.
- `scan_values`: значения по `get_Parameter(guid)` в документе связи.
