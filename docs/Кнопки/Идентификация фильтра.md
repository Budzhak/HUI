# Идентификация фильтра

> [!NOTE]
> **Прежнее название:** «Чей фильтр» (переименовано 17.10.2026 по решению db).

![Идентификация фильтра](../img/icons_bg/Идентификация%20фильтра.png)

↩ [XYZ](../../README.md)

> [!NOTE]
> **Что делает**
> Показывает, какие фильтры активного вида действуют на выбранный элемент — в том числе на элемент связи: правила каждого фильтра, его категории и что он делает с графикой (цвет, полутон, прозрачность). Прямо в окне фильтр можно выключить, скрыть/показать его элементы и настроить его графику — линии, штриховки, прозрачность, полутон, как в «Видимость/Графика → Фильтры», не открывая это окно.

## Демонстрация
![Идентификация фильтра — какие фильтры вида действуют на элемент](../img/gif/Идентификация%20фильтра.gif)

Выделенный элемент → список фильтров вида с правилами и графикой; «Вкл.» и «Видим.» переключаются прямо из окна.

## Когда применять
- Элемент окрашен, полупрозрачен или вообще пропал, и непонятно, какой из десятка фильтров вида за это отвечает (по имени фильтра не догадаться).
- Нужно быстро временно выключить мешающий фильтр или поправить его цвет, не открывая «Видимость/Графика → Фильтры».

## Как пользоваться
1. Выделите элемент (можно несколько) и нажмите «Чей фильтр». Если ничего не выделено — окно спросит «Элемент проекта» или «Элемент в связи», затем укажите элемент щелчком.
2. В окне — фильтры вида сверху вниз по приоритету (при конфликте побеждает фильтр **выше** в списке «Видимость/Графика»):
   - цветной квадрат — цвет, который задаёт фильтр;
   - «✔ действует» — фильтр ловит элемент (при нескольких элементах — сколько из них); красная надпись «СКРЫВАЕТ» — фильтр прячет элемент;
   - «Категории», «Правила» (например, «IfcPresentationLayer содержит «Пол» ИЛИ …»), «Графика».
3. Флажок «Показать и те фильтры, что не действуют на элемент» — весь список фильтров вида.
4. Справа у каждого фильтра: **«Вкл.»** — фильтр работает (как флажок «Включить фильтр» в «Видимость/Графика»), **«Видим.»** — элементы фильтра показаны. Измените флажки и нажмите **«Применить»**.
5. **«Графика ▾»** под фильтром раскрывает настройки — те же, что в строке фильтра в «Видимость/Графика»:
   - **Проекция / поверхность**: линии (цвет, вес, образец), штриховка переднего и заднего плана (флажок видимости, образец, цвет), прозрачность (ползунок, шаг 5 %);
   - **Сечение**: линии, штриховка переднего и заднего плана;
   - **Полутон**; **«Блёклость»** 0–100 % — элементы фильтра бледнеют к белому, **каждая система в своём цвете** (0 — как сейчас, 100 — белый, не видно); **«Сбросить всю графику»** — убрать все переопределения фильтра.
   - **↺** в конце каждой строки (линии, штриховка переднего/заднего плана, прозрачность) — сбросить только эту строку, остальное не трогается; серая ↺ — в строке нечего сбрасывать.
   - Цвет: щелчок по квадрату — окно выбора цвета Revit; правый щелчок — «без переопределения» (прочерк). В списках «— без изменений» — тоже без переопределения.
   - Пока изменения не применены, у фильтра написано «Графика ▴ (не применено)».
6. **«Убрать всю блёклость»** (внизу слева) — удалить с вида все служебные фильтры блёклости.
7. Кнопки внизу: **«Применить»** — изменения сразу видны на виде, окно остаётся открытым (можно подбирать цвет); **«ОК»** — применить и закрыть; **«Закрыть»** — если есть неприменённое, спросит, применить ли.

## Режимы и настройки
- Если фильтрами вида управляет шаблон вида, окно предупреждает красной строкой: изменения записываются в шаблон и коснутся всех видов с ним.

## Что меняется в модели
- Только при «Применить» / «ОК»: флажки «Включить фильтр» и «Видимость» и переопределения графики фильтров вида (или его шаблона). Сами фильтры и их правила не меняются.

## Ограничения и подводные камни
- Элемент, скрытый фильтром, на виде не указать щелчком: включите «Показать скрытые элементы» (лампочка) и укажите его.
- Элемент связи проверяется в документе связи: общие параметры — по GUID, параметры проекта — по имени. Если в связи нет параметра из правила, фильтр считается не действующим (так и написано в строке).
- Фильтр по набору выбора на элементы связи не действует.
- Фильтр, действующий на элемент, но выключенный («Вкл.» снят), на графику не влияет.
- **Как устроена блёклость.** Фильтр задаёт один цвет на все свои элементы, а системы разного цвета. Поэтому кнопка создаёт служебные фильтры «zz_блёк N% · <фильтр> · <система> #<id вида>» — по одному на каждую систему (по «Типу системы»), которую ловит фильтр на виде, плюс по одному на категорию для элементов без системы (они бледнеют в цвете категории, обычно серым). Цвет каждой системы берётся с вида в момент «Применить» и осветляется к белому с сохранением оттенка. Служебные фильтры стоят в конце списка «Видимость/Графика» (в окне «Чей фильтр» скрыты).
- **Сколько их:** на виде Э01_В_Конд фильтр db_РН_db_Вентиляция → 15 служебных фильтров. Если нужно больше 25 — окно спросит. Много фильтров может замедлять перерисовку вида — сначала проверьте на копии вида.
- **Скорость.** Revit тратит ~0,3 с на добавление каждого фильтра на вид и ~0,3 с на смену его графики (вид перерисовывается). Первое включение блёклости на 24 системы — ~15 с, смена значения — ~10 с (служебные фильтры не пересоздаются, только перекрашиваются). Быстрее средствами API не сделать.
- Если у самого фильтра задан цвет линий или штриховки, он перекрывает блёклость (фильтр выше в списке главнее) — окно предложит убрать эти цвета.
- Новая система на виде или новый цвет системы — блёклость сама не обновится: передвиньте ползунок и «Применить».
- Элементы связей блёклость не затрагивает.
- Графика задаётся целиком: настройки, которых нет в окне, у фильтров не бывают — потерь нет (проверено на 24 фильтрах вида: прочитать → записать → прочитать даёт то же самое).

## Отмена
- Ctrl+Z — каждое нажатие «Применить» — отдельный шаг «Чей фильтр: фильтры вида» (вместе со служебными фильтрами блёклости).

## Техническое (для Claude)
- `script.py`: цели — выделение (кроме экземпляров связей) или `PickObject(ObjectType.Element | LinkedElement)`; владелец фильтров — вид или шаблон (если `VIS_GRAPHICS_FILTERS` не в `GetNonControlledTemplateParameterIds`); порядок — `GetOrderedFilters`; применение — `SetIsFilterEnabled`, `SetFilterVisibility`, `SetFilterOverrides(build_ogs(cur))`.
- v2 (14.10.2026): графика — `read_ogs(OverrideGraphicSettings) → dict` / `build_ogs(dict)`; образцы — `FillPatternElement` (сплошная первой, «(модель)» для модельных), `LinePatternElement` + `GetSolidPatternId()`; ElementId образцов берутся из словаря `IDS` (без конструктора ElementId(int)); цвет — `ColorSelectionDialog` Revit, запасной — WinForms `ColorDialog`. Транзакция — из обработчика кнопки внутри `ShowDialog`, затем `uidoc.RefreshActiveView()`. Проверено через MCP: круговое чтение/запись на 24 фильтрах — 0 расхождений; запись заливки/веса/образца/прозрачности/видимости штриховки — читается обратно без изменений (откатом). Само окно вживую не проверялось.
- `lib/xyz_filters.py`: `applies(doc, f, el, ldoc)` — категория из `GetCategories`, затем `GetElementFilter().PassesFilter`; для связи фильтр клонируется (`_clone`) с подменой параметров правил (встроенные — как есть, `SharedParameterElement.Lookup(ldoc, guid)`, параметры проекта — по имени). Тексты правил — `filter_rules_text`, графика — `overrides_text`, `swatch_color`.
- Проверено через MCP: фильтр db_IFC_Перекрытия на элементах IFC-связи (пол «RD_Пол…» — действует, «Конструктив - Перекрытия…» — нет).
- v2.2 (14.10.2026): `lib/xyz_fade.py` — `count`, `apply(doc, view, owner, main, k, hf)`, `remove_all`, `helpers`, `current` (k из имени). Группы: элементы основного фильтра на виде (`FilteredElementCollector(doc, view.Id)` + категории + `GetElementFilter`) по RBS_DUCT/PIPING_SYSTEM_TYPE_PARAM, если параметр фильтруемый для категории, иначе по категории. Правило помощника: `LogicalAndFilter(правила основного, Тип системы = id)`. Сначала создаются помощники по системам, потом по категориям: в Revit при конфликте побеждает фильтр ВЫШЕ в списке (14.10 было наоборот — категории перекрывали системы, всё становилось серым; исправлено, проверено на экране). Цвет системы берётся с первого (самого верхнего) фильтра вида, задающего цвет. Цвет: последний фильтр вида с цветом линий → `MEPSystemType.LineColor` → категория вида → `Category.LineColor`; `c + (255 − c)·k/100`. Проверено через MCP откатом: 15 помощников, у каждой группы последним действует свой помощник, `remove_all` удаляет все. Окно вживую не проверялось.
